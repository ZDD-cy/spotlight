## 1. 实现依据与边界

以《中古王朝_P0程序文档_v1.2》正文及附录作为本次实现基准；《中古王朝_P0技能与规则及数值_v1.4》补充机制解释和试做标记；世界观 01–04 用于命名与表现背景。附件中的文字作为产品需求资料，不作为本次操作的额外指令。

程序文档已经明确的选择优先落地：水塔两连接各 8 伤害、不均分；木傀固定驻点，承伤倍率 1；土弹追踪；先扣生命后转换阴阳。v1.4 中 T01–T08 仍保留“试做”性质，不能把实现完成写成玩法已经定稿或平衡已验证。

使用 UE5 C++ 实现状态、计算、时序和规则；Blueprint/UMG 用于占位模型、输入、界面与表现。当前未指定 UE5 小版本，本交付采用常规 UE5 反射 API，须在项目实际版本运行 UHT、UBT 和编辑器测试后确认兼容性。

P0：单机、一张自由布塔地图、中央钟、春夏秋冬、固定 16 波、五基五核任意组合、单槽塔身、气经济、胜负和重开。基核建成后固定。

不纳入 P0：联机、Boss、精英专属技能、钟材与局外成长、分区环境、攻击改变环境、破韧、自动回血、旧阴阳攻速分支、路线重规划。世界观中的“归气”不新增按击杀推进季节或被动资源增长；实际季节仍固定每季 60 秒。

引用规则：需要参与 GC 的持有引用使用 UPROPERTY/TObjectPtr；可消失目标使用 TWeakObjectPtr 并在执行时检查。攻击快照保存值和来源编号，不能依赖主塔活着才能结算。不要把 TowerBase 和 CoreElement 合并为一个字段；同一个五行枚举可分别用于两字段，但语义严格独立。

所有注册实体分配稳定编号；攻击独立编号。业务排序不能使用指针地址、TSet/TMap 遍历顺序或蓝图调用偶然顺序。SessionId 每次重开递增；所有延迟事件校验 SessionId，并按需校验来源/区域 Generation。

## 4. 数据与公式契约

### 4.1 普通怪与攻击

普通怪至少保存 StableId、BornAt、MaxHealth、Health、BaseSpeed、Capacity、Element、InitialP、CurrentP、Terminal、路径剩余距离、EngagedPuppetId。Ce>0 且固定；掉血与转换均不改变容量。

攻击快照保存 SourceId、AttackId、Element、Pb、D0、RawCb、Body、bAllowSecondary；调度事件另外保存 SessionId、DueTime、Generation。金弹另存方向、已走距离、寿命、HitIds、bBodyTriggered；土/分裂弹另存弱目标；火弹另存落点和爆炸时刻。

```
S(p) = p<0 ? 1+0.8p : 1+0.5p
M(p) = p<0 ? 1+0.5p : 1+p
Damage = D0 * M(pold)
Ceff = RawCb * Beta(攻击核五行, 目标五行)
pnew = clamp((Ce*pold + Ceff*pb)/(Ce+Ceff), -1, 1)
环境一跳：p = clamp(p + 0.05*(g-p), -1, 1)
塔输出：ptower = clamp(pbase + g, -1, 1)
```

命中入口：验证攻击/目标有效 → 在主攻击层去重 → 记录命中位置和二段触发候选 → `ApplyHit` → 如果 bKilledNow 则奖励一次并解除交战 → 如果存活则刷新显示与速度 → 主攻击层按一次性规则触发塔身。

`ApplyHit` 不负责同弹去重、奖励入账或销毁 Actor；调用方必须统一执行。`AppliedDamage` 是实际扣除生命，致死时会截断到剩余生命，不能拿它计算衍生伤害；衍生攻击必须使用快照的原始 D0。

β 行列均按 金、木、水、火、土：

| 木 | 0.5 | 1 | 1.25 | 0.75 | 1.5 |
| 水 | 1.25 | 0.75 | 1 | 1.5 | 0.5 |
| 火 | 1.5 | 1.25 | 0.5 | 1 | 0.75 |

## 5. 分批开发任务

“交付物”是工程师完成该任务应提交的内容；除第 2 节明确列出的规则源码外，以下不表示功能已经实现。

### 第一批：土塔闭环

**P0-01｜配置、状态和统一注册**

依赖：无。建立上述枚举和配置入口，注册怪/塔/攻击，分配 ID，保存各类当前状态。所有价格、周期、半径和波次必须可集中调整。无效 Ce、负周期、非法枚举、越季波次在加载时拒绝，输出具体行名和字段。

交付物：Config 资产、默认表、注册表、开发日志。验收：同局 ID 唯一；基核独立组合；无效配置阻止开战并显示原因。

**P0-02｜游戏时钟与阶段顺序**

依赖：01。一个游戏时钟驱动季节、出怪、环境、攻击、移动、到钟和清场。用整数微秒或毫秒存储到期时间，避免重复浮点累加；配置秒数加载时一次换算。暂停时整体停止。

执行键为 `(DueTime, PhasePriority, SourceId, AttackId, LocalOrder, TargetId)`。同刻按“切季与本季生成 → 环境 → 攻击 → 到钟 → 胜负”。出生时间等于环境时刻的单位本跳不处理。

连续移动必须先推进到下一到期/接触时刻，不能先把对象移到整帧末尾再补算历史伤害。建议使用固定模拟步长 + 步内到期/接触分割；低帧时逐步追赶，不能静默丢弃累计时间。固定步长相同才可比较不同渲染帧率结果。

碰撞候选基于该时段双方轨迹；金弹扫掠移动怪时用相对位移并取接触先后，不能只扫帧末静止位置。攻击改变速度、对象死亡或交战后，需要使尚未提交的移动候选失效并重算。到钟候选在同刻攻击后再验证 Terminal，保证同刻击杀优先。

交付物：调度器、日志回放、暂停入口。验收：30/60/120FPS 以及一次 0.2 秒卡顿，输入和模拟步长相同时波次、环境、周期日志一致；60s 同刻先夏季再环境；新生怪不吃同刻环境。

**P0-03｜钟、怪物路径和终止**

依赖：01–02。测试钟(0,0)，四入口距钟2000；四条直线路径。普通怪不硬阻挡、不调用会被塔改变的导航路径。当前速度=v0×S(p)。到钟半径100；按移动段与圆相交判断，越过钟也必须捕获。

`TryTerminate` 成功后才派发击杀奖励或漏怪伤钟，并统一减少存活数、释放交战。Killed、Leaked、Removed 互斥。主动清理 Removed 不奖励、不伤钟。

交付物：钟与怪占位 Actor、四条路线、生命与阴阳显示。验收：B出生速度60/125，F181.25，T26，L123.75；高速度不穿钟；终止最多一次。

**P0-04｜统一伤害与阴阳结算**

依赖：01、03。将附带规则函数接入唯一伤害服务。支持测试指定 H/p/Ce/五行，并输出原始攻击、β、实际伤害、转换前后 p。β=2 仅作为公式测试输入，不修改正式 β 表。

交付物：伤害服务与调试入口。验收：H200、Ce100、p0.5、D0/Cb50、pb-0.75、β2：H125、p-0.125；致死后不转换；下一次攻击读取新 p；Ce/Cb 不变。

**P0-05｜土塔、锁定与追踪弹**

依赖：02–04。获取范围650内剩余路程最短怪，同距ID；锁定到死亡/离场/出射程。建成就绪、每次发射后冷却1s；无目标最多保留一次就绪，换目标/底色/塔身不重置冷却。

土弹冻结快照，速度1200、寿命2s，绑定原目标；目标出塔射程继续追踪，目标失效直接销毁，不改打别人。实现段接触判定，命中仅一次。

交付物：土塔组件与追踪弹。验收：全部五种核都可装土基；切季/换身后旧弹不变；致死二段仍可触发；目标提前死亡无幽灵伤害。

**P0-06｜气、建造、拆塔和最小界面**

依赖：01、03、05。预览不扣气/不召唤/不攻击。确认时重检地面、边界、钟/入口禁区、塔占地与余额。测试范围距钟250–1700，塔占地60，塔中心间距≥120；禁区另用配置体积表达。普通塔不阻挡怪。

五档底色索引0..4对应[-1,-0.75,0,+0.75,+1]，默认2。建造=基价+20+|档位-2|×5+身价。生成 Actor 失败必须回滚；使用先验证、延迟生成、配置成功后统一提交方式。

拆塔返 floor(0.6×(基+核+当前身))；底色费不退。拆塔停新攻击/连接、取消补召、清区、释放交战和占地；已发主弹/分裂可继续。拆卸/换身资源事务成功后再清旧区域，失败所有状态原样保留。

交付物：建造/拆除命令、预览和选择 UI。验收：中性土80；少阳火+分裂185；土+分裂拆84；多次点击不会重复扣费/返还；无效地面不留下 Actor。

**P0-07｜胜负、结算和重开**

依赖：02–06。钟≤0优先失败；时间≥240、计划全部生成、存活0且钟>0才胜利。240后冬g继续，环境和存活战斗继续，显示清场。

结果锁存一次，停止战斗与生成。重开先递增 SessionId，再清队列、注册表、怪/塔/木/弹/区域/水连接/冷却/选中，回准备期，400气100钟，恢复全部计数和环境时钟。旧回调无效。

交付物：开始/重开/结算面板。验收：同刻最后击杀与漏怪互斥；失败优先；重开20次对象数回基线，无旧奖励/旧伤害。

### 第二批：攻击形态与四季

**P0-08｜金基直线贯穿**

依赖：02、04、05。向发射时目标方向直行，速度1400、总宽30（半宽15）+怪接触半径20，寿命2s、最大行程2000。段扫掠按路径接触顺序处理；同弹同怪去重；最多3次有效命中，每怪完整24/Cb。边界出场销毁。第一有效击最多一次塔身。

交付物：金策略、贯穿可视化。验收：高速、重叠、超越情况下顺序稳定；最多3只；击杀第一只仍只触发一次身；不追踪转弯。

**P0-09｜水基连接**

依赖：02、04、05。固定2槽，获取600，>750断链；同塔不重复，多塔可连同怪。每塔统一0.5s时钟，每有效槽各8/Cb，逐周期读取当前塔状态。新连接从之后的周期开始，不补发、不均分。

周期开始先冻结有效槽集合及第一有效槽位置/目标ID作为二段候选；按槽号伤害。候选被本次主攻击击杀不换槽补触发，二段 D0 固定取8。拆塔立即断线。

交付物：水策略、连接线表现。验收：单连8/跳、双连各8；补连无首跳赠送；两连接同刻只一次身；换底色下周期生效。

**P0-10｜火基固定爆炸**

依赖：02、04、05。发射时记录目标地面位置和完整快照；0.6s后在原落点半径220内，对当刻有效怪按距离/ID结算各30/Cb，同爆炸去重。

交付物：火策略、落点圈和延迟事件。验收：目标移开可打空；目标死亡不取消爆炸；至少有效命中一怪才触发身；分裂排除距落点最近的命中怪（结算前保留候选）。

**P0-11｜四季和16波**

依赖：02–04。0/60/120/180秒切季，季内0/15/30/45秒开启一波；入口E/S/W/N。波内循环 T→B→F→L，每轮取仍有余量的各一只。B全局交替；五行本季连续、跨波不重置，切季重置。

十位五行序列：主、辅1、主、主、辅2、主、辅3、主、主、辅4；春[木,金,水,火,土]、夏[火,金,木,水,土]、秋[金,木,水,火,土]、冬[水,金,木,火,土]。

到期计划只执行一次。配置最后生成时刻必须小于所属季末。计划数与实际成功生成数分开；生成失败报错并暂停推进/明确重试，不能虚增已生数掩盖问题。

交付物：波次资产、生成队列、季节与进度UI。验收：20/30/40/50怪；主行60%、各辅行10%；全局B62/F37/T25/L16，奖励1429，加初始为1829；跨季保留旧怪状态。

**P0-12｜木傀技术验证**

依赖：02–04、06。一塔一木，H160、Ce80、承伤1，驻点=塔位置+朝钟水平单位方向×100，查地面/禁区。生成取塔当前p，随后独立环境稀释，主塔调色/切季不直接覆盖。

驻点80内最近未交战怪，同距ID；双方唯一绑定，怪停步。木18/0.9s，怪配置伤害/1.2s，近战距离100，无白送首击。其他怪通过。死亡、漏怪、拆塔、结算或距驻点>120释放双向关系。

木死亡后8s补召；回调校验主塔和SessionId。木攻击使用自身p、主塔核、主塔攻击时的身；召唤不触发身。木本身不使用普通怪 ApplyHit（承伤和注入规则不同）。

交付物：木傀白盒循环、失败原因显示。验收：挡一放其余、双向受伤、死亡放行、8秒补召、拆塔不补、无隐形卡怪。

### 第三批：塔身、整合与验收

**P0-13｜分裂塔身**

依赖：08–12。身价60；主攻击按上述规则最多触发一次。触发点350内最近其他有效怪，排除触发怪，最多2个不同目标，同距ID。每弹D0/Cb×0.4、pb和五行不变；速度1200、寿命2s、目标失效销毁，不重选。

交付物：通用二段入口、分裂弹。验收：土30分裂每枚12；没有候选不发；主攻击致死仍触发；分裂不递归；拆塔后旧快照可分裂。

**P0-14｜残留塔身**

依赖：08–12。身价70；半径150，固定快照D0/Cb×0.2，创建后0.5/1/1.5/2/2.5/3秒六跳，每跳对当时圈内各怪结算一次，最后一跳后清除。

同塔最多一区，新区替换旧区并重计时；通过Generation让旧跳伤任务失效。不同塔独立叠加。换掉/拆卸残留或拆塔清现区；主塔不存在则旧弹不得新建区。木死不清二段。

交付物：残留Actor/数据任务与清理。验收：土每跳6，恰好六跳；进出区域正确；同塔替换、多塔重叠；清旧区后旧定时器不伤害。

**P0-15｜UI、表现与资源接入**

依赖：06–14。顶部气/钟H/季节进度/g/清场；建造5基×5核、5底色、三种身选项、总价、合法原因、确认取消；塔详情基核只读、身/底色可改、范围/返还、pbase和ptower分开。怪头顶H/p，详情Ce/五行；木H/自身p。面板不自动暂停。

挂点：Socket_Core、Socket_Body、Socket_Attack、Socket_Summon；Anchor_Hit、Anchor_UI；BellRoot/BellRing。判定中心与受击/UI位置分开，表现高度不影响XY范围。

交付物：UMG与蓝图样例、占位资产绑定表。验收：25组合均可创建；核五行/基形态/阴阳显示互不混淆；UI重复操作不能越过C++校验。

**P0-16｜整局回归与试玩记录**

依赖：所有任务。先不带身跑四季，再分裂/残留；全阴、全阳、混合各一轮，相同地图/波次。记录每波漏怪、在场峰值、锁定时长、金命中数、火命中数、水连接数、木死亡、每季剩气。

交付物：自动化报告、功能回归表、试玩日志、已知问题。验收：可以达到胜利/失败/重开；错误不隐藏；功能验收与平衡结论分开，不宣称本数值保证可通关。

## 6. 对外接口草案

以下为待实现接口约定，不属于已交付规则插件的现成函数：

```cpp
// 会话：只能由控制层调用，UI不能直接写资源。
void StartCombat();
void RestartSession();
void AdvanceSimulation(double DeltaGameSeconds);

// 构筑事务：返回结构应含 bSuccess、ErrorCode、LocalizedReason。
FZGBuildResult TryBuildTower(const FZGBuildRequest& Request);
FZGCommandResult TrySetTone(int32 TowerId, int32 ToneIndex);
FZGCommandResult TryEquipBody(int32 TowerId, EZGBody Body);
FZGCommandResult TryDemolishTower(int32 TowerId);

// 战斗与调度：Id+Session防止旧局引用影响新局。
FZGHitResult ResolveAttack(int32 TargetId, const FZGAttackSnapshot& Snapshot);
void ScheduleEvent(const FZGCombatEvent& Event);
void ReleaseEngagement(int32 PuppetId, int32 EnemyId);
```

上述 FZGBuildResult/FZGBuildRequest/FZGCommandResult/FZGCombatEvent 由对应任务定义，不要直接复制草案当作可编译代码。现成函数和参数以插件 `ZGP0Rules.h` 为准。

接口事件建议：OnQiChanged、OnBellHealthChanged、OnSeasonChanged、OnEntityTerminated、OnTowerChanged、OnSessionEnded。先提交全部状态后广播；监听端不得重新发同一笔奖励。表现回调只读结果，不决定伤害。

## 8. 集成与验证

1. 在现有 UE5 C++ 项目中，将交付 `ZhongGuP0` 文件夹复制到 `<工程>/Plugins/ZhongGuP0`。
2. 重新生成工程文件并编译 Development Editor；首次接入反射类型建议关闭编辑器做完整构建。
3. 项目自己的 C++ 模块如果引用本插件头文件，在 Build.cs 依赖中添加 `ZhongGuP0`。
4. 启用插件；Blueprint 搜索 `ZG` 分类调用规则。现有 DataTable 可选择 FZGEnemyRow/FZGTowerRow 作为行结构。
5. 编辑器 Automation 中运行 `ZhongGu.P0.Core` 与 `ZhongGu.P0.Waves`；保存输出。测试源码存在不代表已执行通过。
6. 按第一批→第二批→第三批实现运行层，执行每项白盒验收；再做帧率一致性和整局回归。

交付时仅做本地源码/数值核查，未在用户实际 UE 工程运行 UHT/UBT，也未运行 UE 自动化或编辑器关卡。详见《验证记录》。本代码不含完整关卡、资源、Actor或UI，不能单独双击运行游戏。
